## Delivered behavior

| Area | Concrete change |
|---|---|
| Scheduling | The runtime uses the clock-injected scheduler tested with mock fences. Opt-in observed-budget admission retains an observed-cost envelope, invalidates stale/environment-mismatched observations, accounts for joint deadline demand and repeated dispatch costs, and preserves infeasible work. Fixed progressive is a separate constant-batch policy. Deadline, adaptive-cost, hotset and cost-priority controls are independent. |
| Ownership | Cancellation does not become completion. In-flight owners survive cancellation/unload until a proven fence. Native phase collections resolve only after their shader dependencies are available, and must match the complete plan state count. |
| Reload | A scene re-request during pending unload returns `Deferred` and retries after retirement. Cancelled deferred requests cannot revive. `IsPhaseUnloading` exposes retirement separately from a terminal cancellation state. Activation numbers survive full release/re-registration of the same phase. |
| Native application | The optional UPM observer reads original Entities SubScene requests/readiness across client worlds. It creates no meshes/materials, camera route or gameplay substitute. An explicit build helper binds the original Menu/Main build order, exact Editor version and D3D12-only settings to actual build-input capture. |
| Feedback | Full-plan tracing is armed only when every source collection resolves completely. Scene readiness attempts that explicit arming. Missing/unarmed/errored feedback stays unavailable; report consumers no longer accept default zeros, missing plan hashes, cancelled work, or a new strategy name as valid evidence. |
| Production files | Atomic replacement preserves the previous good file on publication failure. Relative collection paths enforce portable containment rules. Non-finite plan/JSON numbers and invalid counts fail validation; temporary native collections are released after metadata checks. |
| Validation | A named CPU allowlist and Windows/Linux PR workflow exclude runtime runners. Separate compilation projects check actual Core, Runtime, Editor and native-adapter assembly boundaries. The real mock scheduler serializer is validated against the scheduling sidecar Schema. |

`scheduled` remains the default. New policies are explicit selections and have no
measured speedup. The scheduler cannot preempt an opaque native batch or promise a
hard latency bound. A bulk batch that cannot fit estimated interactive headroom
stays deferred until the host declares a suitable existing loading window; the
native observer does not invent one or change the upstream rendering route.

## Unverified runtime scope and historical evidence

Full host asset hydration/import, resolved UPM overlay, Entities generation, shader
compilation, native Player build, rendering correctness, native fences, first-draw
coverage, complete application-frame behavior and comparative latency remain
unverified. The observer does not own the upstream scene's asset leases or delay
unloading; applications requiring that guarantee must use an explicit retained
asset owner such as the separate Addressables integration. Readiness may occur
after a first draw; later feedback cannot recover earlier events.

The four policy arms share one declared player/shader/plan/state/route/cache
contract. Those actual identities remain null until produced. The pinned 6000.1
bulk adapter does not implement the fixed-progressive control; it fails explicitly.
Using a newer Editor requires a separate locked cell for every arm, with a fresh
dependency/build identity. Cold disables the warmup orchestrator, so an absent cold
feedback receipt cannot be counted as zero misses.

Historical warmup-window P95 **127.0 → 12.9 ms**, total completion
**643.5 → 774.6 ms**, the **178.9 ms** outlier, and post-warmup workload P95
**4.169 versus 4.210 ms** remain labelled with the old report. The **88.2%**
warmup-versus-cold improvement does not isolate this scheduler's value. None is
reissued as a result for the new source, and the outlier is not claimed fixed.
The older Megacity experiment also retains its generated-material and restricted
view semantics instead of becoming evidence for the original-scene adapter.
